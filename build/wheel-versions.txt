# EVERY Python package in the image, and none of them from Debian.
# docs/adr/0002-python-dependencies-from-pinned-wheels.md holds the decision.
#
# This file is DERIVED, and `pyproject.toml` plus `uv.lock` are the source:
#
#   uv export --frozen --no-emit-project --no-annotate --no-header              # appliance
#   uv export --frozen --no-emit-project --no-annotate --no-header --extra test # both tiers
#
# Regenerate with: sh build/gather-wheel-versions.sh
#
# WHY NOT THE HASHES HERE. `uv.lock` already carries a sha256 for every artifact of every
# package, and build/fetch-inputs.sh reads them from there. Copying them into a second
# file would create two places for one fact and no mechanism to keep them equal — the
# exact failure mode `docs/reproducible-build.md` exists to prevent. So: versions here,
# for a human to read in a diff; hashes in `uv.lock`, for the build to gate on; and
# build/inputs.sha256, which is what actually stops the build, derived from the lock.
#
# The `# @group` markers are MACHINE-READABLE AND LOAD-BEARING, exactly as in
# build/apt-versions.txt: build/Dockerfile.test installs BOTH groups, build/mkiso.sh
# installs the appliance group ONLY, and build/verify.py fails the build if a name from
# the harness group reaches the rootfs. A package outside any group is a parse error.
#
# Three of these ship prebuilt binaries — cryptography (its own Rust and OpenSSL),
# pillow, zxing-cpp — and argon2-cffi-bindings and cffi compile against libffi. The ADR
# draws the line at where a blob lives: in the input archive, hash-pinned and published,
# it is no different in kind from a .deb; in the repository it would be. `embit` stays
# vendored from source for that reason and its own wheel stays out.
